# Grouped Twin Search — повторная проверка

Дата: 2026-11-12. Сервер `http://127.0.0.1:8080` после перезапуска, база `wnr`.

Заголовки: `DomainId: f67ad556-dd27-4871-9a00-16fb0e8a4102`, `AuthToken: 608c6d7d-99c8-4d87-89c6-2f72d0f5d673,9a3f6075-f175-41cd-a804-934201ec969c`, `Channel: WEB`.

Контракт другой. `POST /private/twin/search/grouped/v1` больше не принимает `groupFieldId`. В теле список `criteria` от 1 до 3 уровней. Уровень — `FIELD` (`fieldId`, `sort`) или `LINK` (`linkId`, `nodeEnd`, `sort`). `search.twinClassIdList` содержит ровно один класс. Листья только на последнем уровне, выше — вложенные `groups`. `count` — число различных листьев поддерева.

Класс `TASK` `7c027b60-0f6c-445c-9889-8ee3855d2c59`, 855 задач. Link для S1–S4: `60f013ff-e7cc-41c9-9d5e-af5e4b2b6586`, конец `DST`. Строка связи есть у 34 задач, у трёх из них больше одного `dst`. Протокол: `checks.json`.

Листья видны при `showTwinMode=DETAILED`. Пользователи — `showTwin2UserMode`, статусы — `showTwin2StatusMode`, опция data list — вместе `showDataListOptionMode` и `showTwinField2DataListOptionMode`. В запросах было `lazyRelation=false`.

## Итог

Дерево из статуса, исполнителя и link совпало с плоской выборкой и со строками `twin_link`. Пустые ключи на месте. Фильтр сужает дерево до группировки. Один и два уровня кладут листья на последний уровень. Четвёртый критерий, два класса и повтор критерия отвергаются до выборки. Класс из 5452 твинов вернулся целиком: прежнего потолка 5000 нет.

Два дефекта ключа динамического поля остались. Десятичный ноль по-прежнему три группы. Timestamp сдвигается на пояс JVM.

## Дефекты

### Decimal: три группы с одним нулём

`TASK.progress` (`e454db8e-c8d8-48cb-9684-00abef38ee9e`), один критерий `FIELD`, `KEY_ASC`. HTTP 200, 20 групп. В сыром JSON ключи `0`, `0.0` и `0.00` — это разные масштабы одного числа в `twin_field_decimal`. После разбора JSON все три равны `0`.

### Timestamp: ключ на три часа раньше

`OBJECT_EXT.startDate` (`ae6118ef-f588-3b8b-a87a-5d061e12378e`), класс `b00b43a8-c1ab-3555-9c99-3442e004432f`. В базе `2026-01-01 00:00:00`. В `groupedFieldValues` — `"2025-12-31T21:00:00.000Z"`. Группа одна, `count = 1`.
